# 90-Day Cybersecurity Remediation Roadmap

## Purpose

This roadmap provides a practical plan for addressing the security weaknesses identified during the MedLink cybersecurity assessment.

The activities are divided into three phases over a 90-day period. High-risk issues are given priority, followed by improvements to monitoring, policies, and long-term security management.

---

## Phase 1 — Days 1–30

### Priority: Address Immediate and High-Risk Issues

| Activity                                    | Related Risk | Owner    | Target |
| ------------------------------------------- | ------------ | -------- | ------ |
| Review and disable former employee accounts | R-001        | IT       | Day 7  |
| Review privileged accounts                  | R-002        | IT       | Day 10 |
| Apply critical security patches             | R-003        | IT       | Day 14 |
| Enable MFA for remote and privileged users  | R-009        | IT       | Day 14 |
| Begin phishing awareness training           | R-004        | Security | Day 21 |
| Review important security logs              | R-005        | IT       | Day 21 |
| Review USB usage and exceptions             | R-006        | IT       | Day 30 |

### Expected Outcome

By the end of Phase 1:

* Former employee accounts should be disabled.
* Critical patches should be applied.
* MFA should be enabled for high-risk accounts.
* Security awareness activities should have started.
* Important system logs should be reviewed.
* USB usage should be controlled.

---

## Phase 2 — Days 31–60

### Priority: Improve Security Processes

| Activity                             | Related Risk | Owner      | Target |
| ------------------------------------ | ------------ | ---------- | ------ |
| Conduct backup restoration test      | R-007        | IT         | Day 40 |
| Complete supplier security reviews   | R-008        | Management | Day 45 |
| Review remote-access permissions     | R-009        | IT         | Day 45 |
| Improve physical access controls     | R-010        | Facilities | Day 50 |
| Review security policies             | R-011        | Management | Day 55 |
| Create PII retention requirements    | R-012        | Privacy/IT | Day 60 |
| Conduct quarterly user-access review | R-001/R-002  | IT         | Day 60 |

### Expected Outcome

By the end of Phase 2:

* Backup restoration should have been tested.
* Important suppliers should have been assessed.
* Remote access should be reviewed.
* Physical security weaknesses should be addressed.
* Security policies should have assigned review dates.
* PII retention requirements should be documented.

---

## Phase 3 — Days 61–90

### Priority: Verify and Monitor Improvements

| Activity                                 | Related Risk | Owner      | Target |
| ---------------------------------------- | ------------ | ---------- | ------ |
| Conduct follow-up control assessment     | All          | Security   | Day 70 |
| Review remediation evidence              | All          | Security   | Day 75 |
| Conduct vulnerability and patch review   | R-003        | IT         | Day 75 |
| Conduct phishing simulation              | R-004        | Security   | Day 80 |
| Review audit logs and escalation process | R-005        | IT         | Day 80 |
| Review backup test results               | R-007        | IT         | Day 85 |
| Review supplier remediation actions      | R-008        | Management | Day 85 |
| Update risk register                     | All          | Security   | Day 90 |
| Update POA&M                             | All          | Security   | Day 90 |
| Present security progress to management  | All          | Management | Day 90 |

### Expected Outcome

At the end of the 90-day period, MedLink should have:

* Reviewed the identified security risks.
* Completed or progressed corrective actions.
* Collected evidence of remediation.
* Updated the risk register.
* Updated the POA&M.
* Reassessed previously identified weaknesses.
* Reported security progress to management.

---

## 90-Day Review

At the end of the roadmap, management should review:

1. Which risks have been resolved?
2. Which risks remain open?
3. Which corrective actions are overdue?
4. What new risks have been identified?
5. What additional resources are required?
6. Which controls should be reassessed?

The risk register and POA&M should be updated based on the results of this review.
