# This are there responsibilities

| Role          | Responsibility                                                            |
| ------------- | ------------------------------------------------------------------------- |
| Management    | Approves security policies, resources, risks and major security decisions |
| Security Lead | Coordinates the security programme and reports security performance       |
| IT Team       | Implements and maintains technical security controls                      |
| System Owners | Protect systems and information under their responsibility                |
| HR/Admin      | Supports employee onboarding, transfers and offboarding                   |
| Users/Staff   | Follow security policies and report security incidents                    |

# 2. Security KPI Dashboard

**KPI** means **Key Performance Indicator**.

> **"it help us to know whether MedLink's security programme is actually working"**

Management can look at numbers such as:

- How many employees completed security training?
- How many accounts have MFA?
- How many critical vulnerabilities remain?
- How quickly are incidents resolved?
- How many security incidents occurred?
- How many overdue security actions exist?



# PM — Security KPI Dashboard

## Purpose

The KPI dashboard provides management with measurable information about MedLink's cybersecurity programme.

| KPI | Target | Frequency | Owner | Status |
|---|---:|---|---|---|
| MFA coverage | ≥ 95% | Monthly | IT | Green |
| Security awareness completion | ≥ 95% | Monthly | HR/Security | Green |
| Critical vulnerabilities | 0 overdue | Monthly | IT | Green |
| High vulnerabilities | < 5 overdue | Monthly | IT | Yellow |
| Incidents resolved within SLA | ≥ 90% | Monthly | Security Lead | Green |
| Backup restore test success | 100% | Quarterly | IT | Green |
| Privileged account review | 100% | Quarterly | Security/IT | Green |
| Open high-risk POA&M items | Decreasing | Monthly | Security Lead | Yellow |
| Endpoint protection coverage | ≥ 98% | Monthly | IT | Green |
| Security policy reviews | 100% | Quarterly | Security Lead | Green |

## Status Definitions

- Green = Target achieved
- Yellow = Needs management attention
- Red = Target not achieved / significant risk

## Reporting

The Security Lead reviews the dashboard monthly and presents important security metrics and risks to management during quarterly management reviews.


# PM — 90-Day Security Programme Roadmap

## Purpose

The 90-day roadmap defines the major cybersecurity and privacy improvement activities planned for MedLink.

## Days 1–30 — Assess and Plan

### Activities

- Review security policies.
- Review user and privileged accounts.
- Review system and asset inventory.
- Identify critical vulnerabilities.
- Review current MFA coverage.
- Review security awareness status.
- Review incident-response procedures.
- Review backup arrangements.

### Expected Results

- Updated security baseline.
- Identified security gaps.
- Updated risk and remediation priorities.
- Management visibility of major risks.

---

## Days 31–60 — Improve and Implement

### Activities

- Increase MFA coverage.
- Remediate critical vulnerabilities.
- Remove unnecessary accounts and privileges.
- Conduct security awareness training.
- Improve audit logging and monitoring.
- Review firewall and endpoint configurations.
- Update incident-response procedures.

### Expected Results

- Reduced security weaknesses.
- Improved authentication security.
- Better monitoring.
- Improved employee security awareness.

---

## Days 61–90 — Test and Review

### Activities

- Conduct a backup restoration test.
- Conduct an incident-response tabletop exercise.
- Review privileged accounts.
- Review KPI performance.
- Review open POA&M items.
- Assess progress against security objectives.
- Prepare management security report.

### Expected Results

- Recovery capability tested.
- Incident-response capability evaluated.
- Outstanding risks identified.
- Management receives programme performance report.

## 90-Day Success Criteria

At the end of the 90-day period:

- MFA coverage has improved.
- Critical vulnerabilities have been addressed.
- Security training targets have been achieved.
- Backup recovery has been tested.
- Incident response has been exercised.
- High-risk remediation items are tracked.
- Security KPIs have been reviewed by management.


# PM — Quarterly Management Review Agenda

## Meeting Purpose

To review MedLink's cybersecurity and privacy programme performance, risks, incidents, and improvement activities.

## Meeting Frequency

Quarterly

## Participants

- Management
- Security Lead
- IT Team
- System Owners
- HR/Admin representatives where required

## Agenda

### 1. Opening

- Confirm meeting objectives.
- Review previous meeting actions.

### 2. Security KPI Review

Review:

- MFA coverage
- Security awareness completion
- Vulnerability status
- Incident statistics
- Endpoint protection coverage
- Backup test results
- Privileged account reviews

### 3. Security Incidents

Discuss:

- Major incidents during the quarter.
- Root causes.
- Response effectiveness.
- Lessons learned.
- Corrective actions.

### 4. Risk Review

Review:

- New security risks.
- Existing high-risk issues.
- POA&M/remediation status.
- Changes to the organization's environment.

### 5. Compliance and Policy Review

Review:

- Security policy status.
- Policy review dates.
- Audit findings.
- Compliance requirements.
- Outstanding corrective actions.

### 6. Security Programme Roadmap

Review:

- Completed activities.
- Delayed activities.
- Upcoming activities.
- Required resources.

### 7. Management Decisions

Management should decide:

- Which risks require priority?
- Which corrective actions require additional resources?
- Which policies require updates?
- Which security activities should be prioritized next quarter?

### 8. Action Items

| Action | Owner | Due Date | Priority | Status |
|---|---|---|---|---|
| Review privileged accounts | IT | 2026-10-15 | High | Open |
| Complete security training | HR | 2026-10-30 | Medium | In Progress |
| Remediate critical vulnerabilities | IT | 2026-10-10 | Critical | Open |

### 9. Closing

- Confirm decisions.
- Confirm action owners.
- Confirm deadlines.
- Schedule next quarterly review.
